Homework: Investment Purchase Tracker

COP 5818 · HTML, CSS, and JavaScript · 100 points

Your task

Build a small application that records investment purchases. Enter an investment name, whole-number quantity, and USD price per unit. The application calculates each purchase’s cost, displays the purchase history, and updates the total invested and number of purchases.

Follow the same development process used in our class example: build the HTML, style it with CSS, then connect the form to JavaScript. All step-by-step instructions are comments inside the three starter files. Each step states what you should expect before continuing.

Start here

  1. Extract the ZIP into a folder. Do not edit files inside the ZIP.
  2. Open index.html, styles.css, and script.js in your editor. Keep their names and location unchanged.
  3. Open index.html in your browser. A blank page at the beginning is expected.
  4. Complete H1–H8 in index.html. Put each element inside the parent specified in the comments.
  5. Complete C1–C7 in styles.css. Check the page on wide and narrow windows.
  6. Complete J1–J8 in script.js. Some steps require writing inside a function and adding its call in handleSubmit; follow both instructions.
  7. Save and reload after edits. Use the browser Console for the indicated checks. Reloading clears the purchase array, so re-enter test data when needed.

Use the exact supplied IDs, classes, variable names, object properties, and function names. You may choose readable colors, but preserve the required layout. Keep the instruction comments. Use the class code and slides as references. You do not need a server, framework, database, or installation.

Rules for the application

  • A name must contain non-whitespace text.
  • Quantity must be a whole number from 1 to 10,000.
  • Unit price must be positive, no more than $1,000,000, with at most two decimal places.
  • Each accepted purchase is a separate object, even when its name matches an earlier purchase.
  • Cost = quantity × unit price. Total invested is the sum of purchase costs; count is the array length.
  • After success, update the history and summary, reset the form, and show confirmation.
  • Invalid input produces feedback without changing stored purchases, history, or summary, and without clearing inputs.
  • History remains in entry order and never duplicates entries when rebuilt.
  • All values are in USD. No fees, market-price updates, profit/loss calculations, selling, editing, or deletion are required. Reloading intentionally clears the data.

Submit

Submit one ZIP containing your completed index.html, styles.css, script.js, a screenshot showing the result after check 2, and a short file named reflection.txt.

In reflection.txt, list checks 1–9 as Pass or Needs work. Then answer each question in 1–3 sentences:
